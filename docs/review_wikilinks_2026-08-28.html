一、需求与实现

需求：无 Obsidian 时，生成的 md 用其它软件可读即可；用 Obsidian 时，笔记间要有双向链接（backlinks）。

实现：新增 scripts/knowledge_links.py 作为知识库的链接后处理步骤（knowledge_sync 的最后一步）：扫描 knowledge 目录全部笔记的 frontmatter（title/tags/concepts），为每篇笔记生成「相关笔记」区——用 Obsidian 原生 [[wikilink]] 链到共享 tag/concept 的笔记（按共享数排序，最多 5 条）。幂等：重复运行只替换该区块。

tags: [部署, docker, chat-extractor]

三、过程中发现并修复的问题

问题影响修复
文件名尾空格title 截断 40 字符残留尾空格进文件名 → wikilink target 与文件名不匹配，Obsidian 链接断裂chat_extractor / meeting_recap 生成文件名统一 strip + 替换 Windows 非法字符（<>:"/\|?*）
链接格式抖动「相关笔记」区块首跑与次跑尾换行不一致 → 幂等失败replace 路径统一补尾换行
前置 bug 连锁meeting_recap 适配缺 import time / import re（迁移适配引入）已补（本报告前置轮次修复）

四、使用方式

场景做法
不用 Obsidian什么都不用做——笔记是标准 markdown（frontmatter + 正文），Typora / VSCode / 任何编辑器可读；[[链接]] 显示为文本
用 Obsidian二选一：① 把 WIKI_DIR（默认 ~/wiki）直接设为 vault 内的目录；② 用 Obsidian「打开文件夹作为仓库」指向 ~/wiki。打开后相关笔记自动变为可点击链接，backlinks 面板自动显示反向引用
链接重建python scripts/knowledge_links.py（或作为 knowledge_sync 的最后一步自动跑）

链接语义：[[文件名|标题]] —— Obsidian 按文件名解析链接（文件名即去扩展名的笔记名），| 后为显示别名。共享任意 tag/concept 即视为相关，按共享数排序取前 5。

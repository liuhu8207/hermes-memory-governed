一、项目定位与设计理念

hermes-memory-governed 是 Hermes Agent 的记忆 provider 插件（memory-provider kind），把「AI 长期记忆」拆成五个信任层级，并给自动提取的内容加一道人工审查门禁。它解决的问题：

  • AI 上下文有限 → 手写规则（L1）始终注入、语义记忆（L2）按相关度召回、对话归档（L3）全文可检索、人格摘要（L4）进系统提示
  • 自动提取的记忆不可靠 → 低置信内容进入 Bridge（JSONL + review-required 标签），人工确认后才导入
  • 长对话压缩丢信息 → 压缩前把关键决策/工具输出转成 Mermaid 任务画布（可选）
  • 检索延迟影响响应 → 异步预取（本轮结束后就为下一轮准备记忆），缓存命中 <1ms

四条设计原则

  • 信任分层：人工手写 > 审查通过 > 自动提取，每层有明确信任级别和注入方式
  • 读写分离：L3 归档同步写（WAL，<10ms 保数据安全），L2 索引异步写（不阻塞对话）
  • 优雅降级：任何依赖缺失（lancedb / sentence-transformers / pandas）都降级到可用路径，绝不崩溃
  • 确定性维护：记忆的长期整理（人格生成、候选导出、健康报告）由 cron 跑确定性脚本，不靠 LLM

二、分层记忆架构总览

L1 · 手写规则MEMORY.md / USER.md，人工维护，最高信任。60s 缓存刷新，始终注入（固定预算 800 tokens）。支持 add / replace / remove 三种写入语义。始终注入
L2 · 语义记忆LanceDB 向量库。双路径：有 embedding 模型（sentence-transformers, 384 维）→ 向量搜索；没有 → 文本子串扫描。自动提取的事实经异步队列写入。按相关度
L3 · 对话归档SQLite + FTS5 全文索引。英文走 FTS5，中文走 LIKE 降级，混合查询双路径合并去重。带 7 天半衰期时间衰减与组内 min-max 归一化。可检索
L4 · 人格摘要persona.md，由 cron 每日从 L1/L2/L3 汇总生成，注入系统提示（User Profile 区块），30 分钟缓存。固定注入
Bridge · 审查门禁自动提取的持久记忆候选 → candidates.jsonl（追加 + id 去重 + 500 行自动归档），secret 模式拦截 + 目标白名单，review-required 标签，人工确认后导入。人工把关
Mermaid 压缩（可选）上下文压缩前把最近 20 个关键事件（决策 / 工具输出 / 用户意图）转成 Mermaid 流程图文本，保住关键信息。默认关闭

三、三条数据流

读路径（异步预取，<1ms 命中）

Turn N 结束 └─ queue_prefetch(下一轮查询) └─ 后台线程 → parallel_recall() 独立临时线程池，超时 0.5s~2s 不阻塞 ├─ L2 向量搜索 / 文本扫描 视 embedding 可用性自动选择 ├─ L3 FTS5(英文) + LIKE(中文) 合并 CJK 按段拆分，双路径去重 └─ L4 persona（固定 1.0） └─ 结果写入 _prefetch_cache Turn N+1 开始 └─ prefetch(查询) → 缓存命中 <1ms；未命中回退 L1-only

写路径（L3 同步，L2 异步）

sync_turn(messages) ├─ L3Writer.write() 同步，SQLite WAL，<10ms（数据安全优先） │ └─ messages 主表 + messages_fts（timestamp 类型统一 REAL） └─ WriteQueue.enqueue() 异步后台（体验优先） └─ worker 线程 → 提取原子事实 → 有模型则生成 384 维向量 → LanceDB add └─ 模型首次可用时 → _migrate_null_vectors() 存量 NULL 行 delete+re-add 补向量

维护路径（cron，确定性脚本）

每日 cron（hermes cron add） ├─ 09:10 l4_persona_daily.py L1+L2+L3 → persona.md（secret 脱敏） ├─ 09:15 scope_recall_bridge.py persona/归纳/wiki → candidates.jsonl（追加去重+归档） └─ 09:45 memory_health_report.py 全层健康检查 → health_report.md/json 统一入口：memory_pipeline.py daily | bridge | health | persona

四、核心模块详解

4.1 plugin/memory_governed/_recall.py — RecallEngine（召回引擎，读路径核心）

能力实现要点
L1 检索MEMORY.md + USER.md 合并文本，60s 缓存；provider 层支持 add/replace/remove 回写与缓存失效
L2 检索三路径：向量搜索（有模型且表有 vector 列）→ 文本子串扫描（无模型，score=0.5+命中数×0.1）→ 空表禁用；score = 1.0 − min(距离, 1.0)，越大越相似
L3 检索英文 FTS5（转义特殊字符）/ 中文 LIKE（ESCAPE 转义 %_）/ 混合双路合并去重；分数链路：abs(rank)/(1+abs(rank)) × 时间衰减（7 天半衰期）→ 组内 min-max 归一化（最强=1.0）
L4 检索persona.md 30 分钟缓存，固定 score=1.0
parallel_recall每次调用独立临时线程池（max_workers=3，池间隔离无排队退化）；as_completed 超时收集已完成层，TimeoutError 捕获不崩；shutdown 后降级 _sequential_recall 串行执行
format_recallL1 固定预算 + L2/L3 共享 1200 tokens 预算；MIN_SCORE=0.1 过滤低相关（L3 归一化后与 L2 同量纲，安全）

4.2 plugin/memory_governed/_sync.py — 写路径

组件实现要点
WriteQueue单 worker 后台线程（daemon），队列满丢最旧；stats 带锁；_embed_model 在 __init__ 即初始化为 None（消除 AttributeError 路径）
L2 索引PyArrow schema（content/category/source/timestamp/vector:float32[384]）；有模型生成向量，无模型写 NULL；_migrate_null_vectors 存量 NULL 行 delete+re-add 补向量（pyarrow as_py 判定，无 pandas 依赖）
L3WriterSQLite WAL；主表 + FTS5 表（timestamp REAL 类型一致）；双重 shutdown 幂等

4.3 plugin/memory_governed/_bridge.py — BridgeExporter（审查门禁）

能力实现要点
导出追加模式（并发不覆盖）+ 已有 id 去重（id=sha256(content+source_path)，稳定）+ 超过 500 行自动轮转到 archive/candidates_时间戳.jsonl
安全写前 secret 检测（sk-/ghp_/api_key= 等模式），命中直接跳过；再 redact 兜底；target 白名单 {user, memory, project, ops}
状态get_status：文件存在性 / 大小 / 行数 / 最近导出报告

4.4 __init__.py — GovernedMemoryProvider（宿主接入层）

实现 MemoryProvider 契约的 11 个生命周期方法：initialize / is_available / system_prompt_block / prefetch / queue_prefetch / recall_status / sync_turn / on_pre_compress / on_session_end / on_memory_write / shutdown / handle_tool_call。暴露 3 个 agent 工具：governed_search（跨层检索）、governed_audit（记忆溯源，L1/L4 word-boundary 精确匹配 + L2/L3 语义检索）、governed_health（全层健康）。会话结束时提取持久记忆候选进 Bridge（启发式：偏好关键词 + CJK 加权长度 ≥15 + 排除问句/清单）。通过 entry point hermes.memory_provider = governed 注册。

4.5 scripts/ — 维护脚本（cron 用）

脚本职责

五、关键设计决策与权衡

① 为什么 L3 同步写、L2 异步写？

L3 是"事实源"（source of truth），丢了无法重建；SQLite WAL 写入 <10ms 不影响对话节奏。L2 是"派生索引"（可由 L3 重建），异步丢一批可接受。

② 为什么 L3 分数要组内 min-max 归一化？

FTS5 bm25 rank 是负数且量级随语料变化（实测 1e-6），与 L2 的 0~1 分数相差 6 个数量级。直接用统一阈值会把 L3 全灭（实际发生过）。归一化后：组内最强恒为 1.0（必过阈值）、组内相对差异保留（时间衰减仍在起作用）、与 L2 可比。

③ 为什么每次召回用独立临时池 + shutdown(wait=False)？

共享池会被慢任务占满导致重叠召回排队超时（返回空）；固定 with 语句会 shutdown(wait=True) 阻塞等待慢任务（2s）。独立池 + wait=False 同时满足：池间隔离、不阻塞调用方、线程在任务完成后自行退出（实测 0 泄漏）。代价：进程退出时若有运行中任务会短暂等待。

④ 为什么中文检索走 LIKE 而不是 FTS5？

SQLite FTS5 默认分词器把中文整句当一个 token，子串永远匹配不到（已实测）。LIKE '%…%' 子串匹配是中文场景唯一不依赖分词器的可靠方案；英文仍走 FTS5（精确且快）。混合查询双路合并 + 按 content 去重。

⑤ 为什么 L1 用文件、L2 用向量库、L3 用 SQLite？

L1 是人工编辑的规则，文件最透明可 git 管理；L2 需要相似度检索，向量库是唯一解；L3 是追加型时序归档，SQLite FTS5 零运维且全文检索快。各取所长。

六、配置与使用方式

安装
powershell -ExecutionPolicy Bypass -File install.ps1 或 pip install .（vector extra：pip install ".[vector]" 启用 L2 向量）
插件注册
entry point hermes.memory_provider = plugin.memory_governed:register，宿主自动发现；或在 config.yaml 设 memory.provider: governed
配置文件
$HERMES_HOME/governed_memory.json（JSON 解析失败会 warning 并回退默认值），支持 GOVERNED_* 环境变量覆盖
默认路径
memory/MEMORY.md、USER.md（L1）· memory/l2（LanceDB）· memory/l3/l3.db（L3）· memory/persona.md（L4）· cron/output/scope_recall_bridge（Bridge）
关键调参
recall.l1_budget_tokens=800 / l23_budget_tokens=1200 / parallel_timeout_seconds=2.0 / l3_time_decay_hours=168 · sync.write_queue_maxsize=100 · mermaid_compress.enabled=false
日常运维
python scripts/memory_pipeline.py daily（或 health / bridge / persona 单独跑）；Bridge 候选人工审查后 import
Agent 工具
governed_search（跨层检索）/ governed_audit（记忆溯源）/ governed_health（健康诊断）

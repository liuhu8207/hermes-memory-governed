三、新发现的问题

中_migrate_null_vectors 调用不存在的 API + 依赖缺失，迁移功能完全无效
_sync.py :: _migrate_null_vectors（新增功能）
① self._l2_store.replace_rows(updated_table) — lancedb 0.37.1 的 LanceTable 没有 replace_rows 方法（实测 hasattr=False），调用即 AttributeError；
② table.to_pandas() — 需要 pandas，而 lancedb 安装不带 pandas（当前环境实测未装）→ ImportError；
③ 两个异常都被 except Exception: logger.debug 吞掉 → 迁移永远静默跳过。影响：装上 sentence-transformers 后，存量 NULL vector 数据依然在向量模式下不可见——这个迁移承诺实际没有兑现。
实测（lancedb 0.37.1）： LanceTable.replace_rows 存在: False LanceTable 可用更新 API: update / merge_insert / delete / add pandas 可用: False
修法（不依赖 pandas，delete + re-add）：
def _migrate_null_vectors(self) -> None:
    if self._l2_store is None or self._embed_model is None:
        return
    try:
        rows = self._l2_store.to_arrow().to_pylist()
        null_rows = [r for r in rows if r.get("vector") is None]
        if not null_rows:
            return
        embeddings = self._embed_model.encode([r["content"] for r in null_rows]).tolist()
        self._l2_store.delete("vector IS NULL")
        re_added = [dict(r, vector=emb) for r, emb in zip(null_rows, embeddings)]
        self._l2_store.add(re_added)
        logger.info("L2 migration: re-embedded %d rows", len(null_rows))
    except Exception as e:
        logger.warning("L2 null-vector migration failed: %s", e)  # 至少升级为 warning
另外两点：迁移放在 _init_l2 内联执行，首次打开会阻塞 worker 线程——数据量大时建议挪到独立维护脚本；失败日志建议从 debug 升为 warning（当前静默策略掩盖了本次 API 错误）。

一、总览

按对比报告的价值排序，四个借鉴机制全部落地：①多后端 embedding 抽象（ONNX 优先）②记忆浮现/晋升 ③dream 式整理 ④schema 版本化迁移。每项都有端到端实测，并配了回归测试。落地过程中与其它工具并行加入的 API embedding 功能做了融合而非覆盖：最终 embedding 优先级链 = API（如配置）→ fastembed（ONNX）→ sentence-transformers → 文本降级。

二、四项机制详解

① 多后端 Embedding 抽象层（借鉴 OpenSquilla 的 embedding 降级链）
plugin/memory_governed/_embedding.py（新增）· _config.py VectorConfig.backend · _sync.py / _recall.py 接入
新增 load_embedder(backend, model)：auto = fastembed（ONNX，无 torch，模型自动下载）→ sentence-transformers → None（文本降级）。与另一工具并行加入的 API embedding 融合后，完整优先级链为：API（如配置）→ fastembed → sentence-transformers → 文本降级。config 化：vector.backend / vector.model / vector.dim；建表向量维度以实际后端 dim 为准（本机无 fastembed 时回退 ST/配置值）。ST 模型名改用 config.vector.model（此前硬编码）。fastembed 后端已实现（接口与 ST 完全一致），需要时 pip install fastembed 即启用，无需改代码——本机未实测其模型下载（大文件），ST 路径已实测。
② 记忆浮现/晋升（借鉴 promote 机制）
scripts/memory_promote.py（新增）
扫描 L3 用户消息 → 按归一化内容分组 → 重复出现 ≥N 次（默认 3x）的模式自动生成 Bridge 候选（tags: auto-promoted + review-required——仍走人工审查，不自动落地）。支持 --min-count / --days / --dry-run。实测：3 次重复模式正确识别并导出 Bridge（written=1），单次出现不晋升。
③ Dream 式整理（借鉴 dream consolidation，安全优先）
scripts/memory_dream.py（新增，opt-in）
把超过 N 天（默认 30）的旧会话压缩为「dream:*」摘要写回 L2（category=dream）。LLM 可选：有 key 走抽象摘要，无 key 走提取式降级。原 L3 消息不删（清理交给 l3_retention）。实测：2 个 45 天前旧会话 → 2 条 dream facts 写入 L2，source_rowid 溯源保留。写前检查 L2 表存在性，缺失时提示而非崩溃。
④ Schema 版本化迁移（借鉴 migrations/）
plugin/memory_governed/_migrations.py（新增）· provider.initialize 接入
MIGRATIONS 注册表（版本号 + 幂等函数）+ MigrationRunner（状态存 migrations_state.json）。注册了两个历史迁移（L3 hash 列、L2 source_rowid 列——此前内联的 schema 变更收敛到统一机制）。provider.initialize 自动跑 pending 迁移，幂等可重入。新 schema 演进只需追加 (version, name, fn)。实测：首轮应用 001/002，二次运行无 pending。

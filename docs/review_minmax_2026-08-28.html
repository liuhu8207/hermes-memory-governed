一、总体结论

min-max 归一化的思路本身可行（组内相对比较、天然有界），但实现再次犯了方向错误：score = 1.0 - (raw_rank - min_rank)/range 让 abs(rank) 最大（最相关）的得 0.0、最小（最不相关）的得 1.0——这是连续第三次在 FTS5 rank 方向上犯错（1/(1+x) 递减 → min-max 反向）。实测「新的弱匹配」压过「旧的强匹配」74000 倍。另有两处次要问题。已直接修复为 score = (raw_rank - min_rank)/range（最强=1.0）并移除位置错误的 floor。

二、实测问题

问题 1（严重）方向颠倒：最相关得 0.0，最不相关得 1.0
_recall.py :: _search_l3（score = 1.0 - (raw_rank - min_rank) / rank_range）
FTS5 bm25 语义：rank 为负，绝对值越大越相关。min_rank 是组内最小 abs（最不相关），公式却把「raw_rank = min」映射到 1.0、「raw_rank = max（最相关）」映射到 0.0——注释「best result (smallest |rank|)」同样写反。叠加尾部 max 归一化与 floor，实测「90 天前的强匹配」得分 0.000014，「现在的弱匹配」得分 1.0，弱压强 74000 倍。
修复前实测： [旧(90d) 强匹配(python×4)] score=0.000014 [新(0d) 弱匹配(python×1)] score=1.000000 弱/强 比: 74056.6x ← 排序颠倒
问题 2floor 位置错误，破坏时间衰减语义
同上（score = max(score, 0.1) 在 score * age_factor 之前）
floor 的目的是「保证组内最强能过 MIN_SCORE」，但尾部 max 归一化已经保证组内最强 → 1.0（必过阈值），floor 完全多余；且它把组内最差从 0.0 抬到 0.1，与 age_factor 相乘后再被 max 归一化，导致「新的 floor 噪音」压过「旧的强匹配」——衰减的相对语义被破坏。修复：删除该 floor。
轻微单条命中 0.8 被尾部归一化覆盖为 1.0
rank_range=0 时设计给 0.8（等价命中中间分），但尾部 max 归一化把它拉到 1.0。单条命中给 1.0 语义上也说得通（组内最强），可接受；若要保留 0.8 意图，需跳过尾部归一化或改用固定分。

三、仍存在的问题

高带空格的中文 / 中英混合查询仍失效
_recall.py :: _build_fts_query（CJK 检测只在 len(words) <= 1 时生效）
「今天 天气」split 后 2 个词 → 走 FTS5 OR of quoted terms → 中文 token 依然查不到 → 0 hits。「Python 天气」→ FTS5 只命中 Python 相关，天气相关记忆全部丢失。CJK 检测应改为「查询串任意位置含 CJK 字符就整体走 LIKE（或按词拆分后分别匹配）」。
实测： query='今天 天气' -> 0 hits（库中实际有「今天天气很好」「明天天气怎么样」） query='Python 天气' -> 2 hits，全部为英文内容，天气相关 0 条
高LIKE 降级未转义通配符 % 和 _
_recall.py :: _search_l3_like（WHERE content LIKE ? 直接拼接）
查询含 %（如「50%了」）或 _（如「a_b」）时，LIKE 通配符会把子串匹配变成模式匹配，产生误报。需用 LIKE ? ESCAPE '\' 并转义。
严重parallel_recall 超时阻塞仍未解决
_recall.py :: parallel_recall（with ThreadPoolExecutor 退出 shutdown(wait=True)）
修复 3 只改了 future.result(timeout)，但真正的阻塞源是 with 块退出时的 shutdown(wait=True)：即使超时后提前收集了已完成结果，退出 with 仍要等慢任务跑完。实测配置 0.5s 总耗时 3.00s。方案：不用 with（手动 shutdown(wait=False)），或把线程池设为 daemon。
实测：parallel_timeout_seconds=0.5，慢 L2 3s → 返回 1 条(FAST)，耗时 3.00s
严重pyproject 构建失败原因换了：缺 wheel
pyproject.toml :: build-system.requires
包发现配置已生效（metadata 阶段通过），但 build-system.requires = ["setuptools>=68.0,<69"] 缺 wheel——setuptools 68 的 bdist_wheel 由独立 wheel 包提供，构建隔离环境里没有它 → invalid command 'bdist_wheel'。修复：requires 加 "wheel"。
实测：pip install . --no-deps --dry-run error: invalid command 'bdist_wheel'（metadata 生成成功，wheel 构建失败）

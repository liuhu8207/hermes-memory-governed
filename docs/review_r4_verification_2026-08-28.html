三、遗留问题

中混合查询的 LIKE 匹配范围偏窄：纯中文记忆可能漏召回
_recall.py :: _search_l3 / _search_l3_like（LIKE 用去空格后的完整查询串）
「Python 天气」的 LIKE 部分用的是整串去空格后的 %Python天气%——只能命中同时含「Python」和「天气」的内容，纯中文的「今天天气很好」「明天天气怎么样」不会被召回。实测返回 3 条里 2 条是纯英文 Python 内容，中文天气记忆丢失。建议：LIKE 部分只取查询串中的 CJK 字符段（如「天气」），与 FTS5 的英文部分互补。
实测：query='Python 天气' -> 3 hits: ['Python 天气 python 脚本', 'Python is a programming ', 'I use Python for scripti'] （「今天天气很好」「明天天气怎么样」未召回）
中线程池 daemon 设置是死代码，依赖 GC 隐式清理
_recall.py :: parallel_recall（for t in pool._threads: t.daemon = True）
pool._threads 在 submit 之前是空集合，这段循环实际什么都没做（实测线程 daemon=False）。当前不阻塞是因为线程池对象被 GC 时 __del__ 隐式调用 shutdown(wait=False)——这是隐式依赖，一旦 pool 被外部引用住就会失效；且进程退出时若慢任务线程存活（非 daemon）会阻塞退出。建议：在 initializer 里设 threading.current_thread().daemon = True，并显式 pool.shutdown(wait=False)。

三、已验证的正确修法（PoC 实测通过）

手动池 + shutdown(wait=False)：三个问题同时解决
替换 parallel_recall 中的 with 块
pool = ThreadPoolExecutor(max_workers=3, thread_name_prefix="recall")
try:
    futures = {
        pool.submit(self._search_l2, query): "l2",
        pool.submit(self._search_l3, query): "l3",
        pool.submit(self._get_l4_result): "l4",
    }
    try:
        for future in as_completed(futures, timeout=timeout):
            ...  # 现有收集逻辑不变
    except TimeoutError:
        ...  # 现有超时兜底不变
finally:
    pool.shutdown(wait=False)  # 不阻塞；运行中任务继续，线程完成后自行退出
PoC 实测：① 单次召回 0.51s（不阻塞）② 重叠召回 A/B 均返回 P4（不退化）③ 召回结束时有 4 个 recall 线程（任务运行中的正常暂态），2.5s 后全部退出（0 残留，无泄漏）。
为什么 shutdown(wait=False) 与 with 不同：wait=False 立即返回，不等运行中任务；已提交任务继续跑完，worker 线程随后自行退出——既不阻塞调用方，也不泄漏线程。

注：shutdown(wait=False) 后若进程立即退出，非 daemon 线程会阻塞退出至任务完成（最长约 2s）。若需彻底规避，可在创建后立即把 pool._threads 中线程设 daemon（需在 submit 之后设置才有效），或接受此短暂延迟（长驻进程通常无感）。

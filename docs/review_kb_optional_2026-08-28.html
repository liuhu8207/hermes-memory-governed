一、结论：知识库本来就不依赖 Obsidian

审计旧版后发现：obsidian_sync.py 里的「Obsidian」只是输出格式（markdown + frontmatter 写到 knowledge/ 目录）——它本身没有任何 vault 路径引用，是个纯编排器。知识库存的是普通 markdown，任何 markdown 编辑器都能看；把 WIKI_DIR 指向 Obsidian vault 目录，笔记就自然出现在 Obsidian 里——仅此而已。

二、迁移内容

文件处理
scripts/knowledge_sync.py（原 obsidian_sync）改名 + Obsidian 可选化：docstring 说明「有/无 Obsidian 均可」；run_script 对未迁移的可选子脚本（clipper/feishu/graph）返回 skipped 而非失败，full_sync 不中断
scripts/meeting_recap.py迁移 + L3 schema 适配（conversations 双表 → 扁平 messages 按 session_id 分组；会议判定改 session_id/消息内容关键词；unix float 时间戳适配）；LLM 可选（无 key 走 basic 降级）；补 import time
scripts/dashboard_gen.py原样迁移（只读 knowledge 目录生成 HTML 复盘页）
scripts/wiki_utils.py补齐 retry / load_log（meeting_recap / dashboard_gen 依赖）
scripts/hermes_env.py此前已补 env_int

三、无 Obsidian 管线全貌（实测通过）

L3 对话归档（SQLite） ├─ chat_extractor → wiki/knowledge/chats/*.md 知识型会话提取（关键词 + CJK 加权长度） ├─ meeting_recap → wiki/knowledge/meetings/*.md 会议会话识别 + 纪要（LLM 可选，basic 降级） ├─ dashboard_gen → HERMES_HOME/dashboard/dashboard.html 周复盘 HTML └─ (可选) clipper_sync / feishu_sync / knowledge_graph → 未迁移时 skipped，不影响主流程 统一入口：python scripts/knowledge_sync.py（--chats-only / --meetings-only / --dashboard / full）

四、过程中发现并修复的关键兼容问题

问题根因修复
编排器 subprocess 调子脚本全部静默失败AutoClaw 的 embedded Python（._pth 隔离）里 python script.py 无法 import 同目录模块——chat_extractor/meeting_recap 全部崩run_script 改为 python -c + runpy 包装（注入 SCRIPT_DIR 到 sys.path + 注入 sys.argv）——embedded 与标准 Python 通用
meeting_recap 缺 import timeL3 适配引入了 time.time() 但未加导入补 import time
httpx 未安装pyproject 声明了依赖但本机环境未装（范围版本安装触发 pip 环境 bug）精确版本安装 httpx==0.28.1
